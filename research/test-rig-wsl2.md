## 1. MuseScore 4.x AppImage on WSL2/WSLg

- **No primary-source report of MuseScore 4 under WSLg found.** Searches of musescore.org, GitHub (`repo:musescore/MuseScore WSL|WSLg|"Windows Subsystem for Linux"` returned nothing relevant), Reddit and Ask Ubuntu produced no thread. UNCERTAIN whether it starts; the items below are the adjacent evidence.
- **Forced xcb (important for WSLg and for offscreen).** CONFIRMED from source `src/app/main.cpp` at v4.7.5 and v4.6.2 (absent in v4.5.2 and v4.4.3): under `#ifdef Q_OS_LINUX`: `if (qEnvironmentVariable("MU_QT_QPA_PLATFORM") != "offscreen") qputenv("QT_QPA_PLATFORMTHEME","gtk3");` and `//! NOTE Forced X11, with Wayland there are a number of problems now` / `if (qEnvironmentVariable("MU_QT_QPA_PLATFORM") == "") qputenv("QT_QPA_PLATFORM","xcb");` (https://raw.githubusercontent.com/musescore/MuseScore/v4.7.5/src/app/main.cpp). Consequence: from 4.6 on, plain `QT_QPA_PLATFORM=wayland|offscreen` is overwritten; you must also set `MU_QT_QPA_PLATFORM=<same>`. Confirmed by issue #33922 (4.7.3, closed 2026-06-23): Marc Sabatella: "set the environment variable QT_QPA_PLATFORM=wayland and also MU_QT_QPA_PLATFORM=wayland"; reporter: "Setting both ... got it working" (https://github.com/musescore/MuseScore/issues/33922). Under WSLg this means the AppImage goes to XWayland (`DISPLAY=:0`) by default, which is the better-supported path anyway.
- **Offscreen platform.** CONFIRMED issue #17247 ("Can't run MuseScore CLI in headless mode", still open): `-platform offscreen` is swallowed by MuseScore's own parser, but `QT_QPA_PLATFORM=offscreen ./MuseScore-4.1.0...AppImage -o out.pdf test.mscz` worked ("Ah, looks like that works"); maintainer comment (2023-10-15): "you can set the environment variable QT_QPA_PLATFORM=offscreen to run it headless" (https://github.com/musescore/MuseScore/issues/17247). For 4.6+/4.7.5 add `MU_QT_QPA_PLATFORM=offscreen` (see above). The AppImage bundles the plugin: `make_appimage.sh` sets `EXTRA_PLATFORM_PLUGINS="libqoffscreen.so;libqwayland.so"` and copies wayland client plugins with comment "Wayland support (run with MU_QT_QPA_PLATFORM=wayland to use)" (https://raw.githubusercontent.com/musescore/MuseScore/v4.7.5/buildscripts/ci/linux/tools/make_appimage.sh). UNCERTAIN: whether the GUI run mode (which is what you need for `api.websocketserver`) is stable under offscreen; the issue only tests converter mode. Note that both console and GUI modes instantiate `QApplication` (main.cpp: only `AudioPluginRegistration` uses `QCoreApplication`), so a platform plugin is always required; no truly display-less CLI exists.
- **Qt Quick under WSLg.** CONFIRMED wslg issue #1025: Qt 6 Quick apps show "only one frame ... black background" with `QT_QPA_PLATFORM=xcb` and transparent/no-input with wayland; a commenter: "When running as `LIBGL_ALWAYS_SOFTWARE=1 cool-retro-term`, everything works as expected" (https://github.com/microsoft/wslg/issues/1025). MuseScore 4 is Qt Quick, so keep `LIBGL_ALWAYS_SOFTWARE=1` as the first flag to try. A forum workaround for MS4 rendering is `export QT_QUICK_BACKEND="software"` ("A known trick/workaround for Musescore 4 graphical issues") and the log hint "Could not create EGL surface (EGL error 0x3000)" (https://musescore.org/en/node/377308, via Wayback). `--no-sandbox`, `QTWEBENGINE_DISABLE_SANDBOX`: no MuseScore evidence; MS4 does not ship QtWebEngine (the 4.x parser has no `-w`), so UNCERTAIN/likely irrelevant. `QT_XCB_GL_INTEGRATION=none`: no evidence found.
- **FUSE / `--appimage-extract`.** CONFIRMED: musescore.org download page requires "fuse2 installed to run the AppImage" (via https://musescore.org/en/download search summary); issue #18633: "Just install libfuse2" (22.04+), and the attempt to switch to the new FUSE-free appimagetool "had to revert" (https://github.com/musescore/MuseScore/issues/18633). Extraction fallback is documented for MS4 in #11244: "extract ... `--appimage-extract` ... `cd squashfs-root` ... run `QT_QPA_PLATFORM=wayland ./AppRun`" (https://github.com/musescore/MuseScore/issues/11244). Generic WSL guides use the same `--appimage-extract` + `./squashfs-root/AppRun` recipe (https://longlovemyu.com/appimage_wsl/; https://github.com/winfunc/opcode/issues/352, "Single prereq is libgles2", Ubuntu 24.04 WSL2).
- **Audio.** WSLg provides a PulseAudio server ("WSLg runs a PulseAudio server", https://github.com/microsoft/wslg/blob/main/README.md); MS4 startup only warns about missing jack/pipewire libs (`libjack.so.0` lines in #17247 output). UNCERTAIN that audio absence can crash the GUI; no report found.
- **4.7.5 downloads.** CONFIRMED via GitHub API (tag `v4.7.5`, published 2026-09-08T13:45:04Z): `https://github.com/musescore/MuseScore/releases/download/v4.7.5/MuseScore-Studio-4.7.5.260831071-x86_64.AppImage` (plus `.zsync`, `-aarch64.AppImage`, `.msi`, `.paf.exe`, `.dmg`, `checksums.sha256.txt`). Naming pattern: `MuseScore-Studio-<ver>.<build>-x86_64.AppImage`.

## 3. WSL2 (mirrored) ↔ Windows host sockets

- CONFIRMED (https://learn.microsoft.com/en-us/windows/wsl/networking): mirrored benefits include "Connect to Windows servers from within Linux using the localhost address 127.0.0.1. IPv6 localhost address ::1 is not supported"; and "the Windows host and WSL2 VM can connect to each other using localhost (127.0.0.1)". So WSL→MuseScore (bound to `QHostAddress::Any`) via `ws://127.0.0.1:8765` is the documented path. Prefer the literal `127.0.0.1` over `localhost` to avoid a `::1` attempt (UNCERTAIN how your client resolves `localhost`).
- Firewall: `Get-NetFirewallHyperVVMSetting` has `LoopbackEnabled`: "Tracks if loopback traffic between the host and the container is allowed, without requiring any Hyper-V Firewall rules. WSL enables it by default" (https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/hyper-v-firewall). For the reverse (Windows MuseScore → WSL MCP server) the networking page says to allow inbound: `Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow` or a `New-NetFirewallHyperVRule ... -Direction Inbound ... -LocalPorts 80`. UNCERTAIN whether that is needed for pure loopback given `LoopbackEnabled`.
- `hostAddressLoopback`: "The 127.0.0.1 loopback address can always be used, this option allows for all additionally assigned local IP addresses to be used as well" (https://learn.microsoft.com/en-us/windows/wsl/wsl-config). `ignoredPorts` lets Linux bind ports "even if that port is used in Windows" (same page) — i.e. by default a port bound on Windows is not bindable in Linux (CONFIRMED by implication; Docker "address already in use" reports: https://github.com/microsoft/WSL/issues/40984).
- Known breakage: #40343 (open, WSL 2.6.3, Ubuntu 26.04): "WSL2 client attempts to connect to a Windows host application via 127.0.0.1 in mirrored networking mode, the TCP handshake fails ... Linux kernel ... responds with RST ... even with hostAddressLoopback=true" (https://github.com/microsoft/WSL/issues/40343); #41102 (auto-closed): 127.0.0.1 connections "never complete inside WSL2 while NAT mode works" (https://github.com/microsoft/WSL/issues/41102); #12703: `0.0.0.0` bind not mirrored until a second bind attempt (https://github.com/microsoft/WSL/issues/12703). Test `nc -vz 127.0.0.1 8765` first; fallback is NAT mode + host IP from `ip route show | grep default`.
