## 1. ChatGPT desktop app and local stdio MCP

**CONFIRMED – the two OpenAI pages describe two different surfaces, not a contradiction.**

- https://learn.chatgpt.com/docs/extend/mcp?surface=cli (title "Model Context Protocol", subtitle "Give Codex access to third-party tools and context"; no date). This page is Codex documentation. It says: "ChatGPT web can use remote MCP-backed tools supplied by plugins." / "Local Codex clients can also connect directly to MCP servers and share their configuration." / "The ChatGPT desktop app, Codex CLI, and IDE extension support MCP servers and share MCP configuration for the same Codex host." / "STDIO servers: Servers that run as a local process (started by a command)." / "Open **Settings**, then select **MCP servers**." / "In the composer, type `/mcp` to view connected servers." / "ChatGPT web doesn't read local Codex configuration files or expose the local Codex command menu." So local stdio MCP is a feature of the Codex runtime embedded in the ChatGPT desktop app (same `~/.codex/config.toml`), not of the ChatGPT chat product.
- https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt (fetched via a reader proxy because the site blocks direct fetches; shows "Updated: 1 hour ago"). This describes ChatGPT chat connectors/apps: "ChatGPT connects to remote MCP servers." / "Can I connect to a local MCP server?" – "Not directly." / "...use Secure MCP Tunnel to connect it to supported OpenAI products without exposing the server to the public internet." / "Full MCP (Model Context Protocol) support, including modify/write actions, is rolling out in beta" to Business, Enterprise and Edu. / "Full MCP is only available to Business and Enterprise/Edu users, currently." / "Pro users can connect custom MCP servers with read/fetch permissions." / "Apps and full MCP support are available for ChatGPT Business and Enterprise/Edu customers on ChatGPT web." / mobile: "No - web only."
- Secure MCP Tunnel, https://developers.openai.com/api/docs/guides/secure-mcp-tunnels.md (no date): "Secure MCP Tunnel lets you connect private MCP servers to supported OpenAI products without opening inbound firewall ports." Prerequisites include "A runtime API key for `tunnel-client`", "Tunnels Read + Manage" roles, and "Workspace permission to add custom MCP servers in ChatGPT." It reaches the server "over stdio or HTTP from inside your network" (`--mcp-command` for stdio). It is a Platform (API-key, org-role) feature, and page says it "does not support public plugin submission or distribution."
- Codex approval of write tools (learn.chatgpt.com page): "Supported values are `auto`, `prompt`, `writes`, and `approve`." / "The `writes` mode prompts for tools that aren't marked read-only." / "`tools.<tool>.approval_mode` (optional): Per-tool approval behavior override."

**Answer for an individual Plus/Pro subscriber, Oct 2026:**
- ChatGPT *chat* (web/desktop chat surface): local stdio is not supported ("Not directly"); only remote servers or a Secure MCP Tunnel; write actions only Business/Enterprise/Edu, Pro is read/fetch only. Plus is not mentioned for custom MCP at all.
- Codex surface inside the ChatGPT desktop app, Codex CLI, IDE extension: local STDIO servers with write tools work via Settings > MCP servers / `config.toml`, gated by `approval_mode`. **UNCERTAIN:** whether the desktop "Settings > MCP servers" entry exists on all builds; a third-party LiteLLM guide reports a "Settings → Plugins → MCPs" label in one captured build (https://docs.litellm.ai/docs/proxy/client_setup/codex_chatgpt_desktop). Nothing OpenAI says ties this to Windows vs macOS; the learn site has "Windows > Desktop app" and "Linux > Desktop app" nav entries.

## 2. Codex CLI config and plan requirements

**CONFIRMED** from https://learn.chatgpt.com/docs/extend/mcp.md and https://learn.chatgpt.com/docs/config-file/config-reference (both redirect targets of developers.openai.com/codex/mcp and /codex/config-reference; no dates):
- `[mcp_servers.<name>]` fields: "`command` (required): The command that starts the server." / "`args` (optional): Arguments to pass to the server." / "`env` (optional): Environment variables to set for the server." / "`env_vars` (optional): Environment variables to allow and forward." / "`cwd` (optional): Working directory to start the server from." / "`startup_timeout_sec` (optional): Timeout (seconds) for the server to start. Default: `10`." / "`tool_timeout_sec` (optional): Timeout (seconds) for the server to run a tool. Default: `60`." / "`enabled_tools` (optional): Tool allow list." / "`disabled_tools` (optional): Tool deny list (applied after `enabled_tools`)." / "`enabled` (optional): Set `false` to disable a server without deleting it." The reference also lists `default_tools_approval_mode` (`auto | prompt | writes | approve`), `tools.<tool>.approval_mode`, `tools.<tool>.output_token_limit`, `required`, `startup_timeout_ms`, and HTTP-only keys (`url`, `bearer_token_env_var`, `http_headers`, `oauth.*`).
- `codex mcp add`: "codex mcp add <server-name> --env VAR1=VALUE1 --env VAR2=VALUE2 -- <stdio server-command>", example "codex mcp add context7 -- npx -y @upstash/context7-mcp". Project-scoped `.codex/config.toml` is also read.
- Auth, https://learn.chatgpt.com/docs/auth: "Sign in with ChatGPT for subscription access" / "Sign in with an API key for usage-based access" / "When you sign in with an API key, Codex uses standard API pricing instead of included ChatGPT plan credits." Custom providers: "Codex assumes the provider doesn't require authentication. This is useful for local models." (when `requires_openai_auth` unset and no `env_key`).
- Plans, https://learn.chatgpt.com/docs/pricing: "ChatGPT Work and Codex are included in your ChatGPT Free, Go, Plus, Pro, Business, Edu, or Enterprise plan." (page dated by "GPT-5.5 retires from Codex with ChatGPT sign-in on October 14, 2026".) So the owner needs no separate "Codex plan": any ChatGPT login (even Free) or an API key works, and a local model provider needs neither. **UNCERTAIN:** Free-tier usage caps; third-party posts conflict on whether Free includes Codex (OpenAI's own pricing page says it does).

## 4. Claude Code

**CONFIRMED** from https://code.claude.com/docs/en/cli-reference, /mcp, /headless, /permissions (pages carry version numbers up to v2.1.296, no dates):
- `.mcp.json`: "Project-scoped servers enable team collaboration by storing configurations in a `.mcp.json` file at your project's root directory." Format `{"mcpServers": {"name": {"type": "http", "url": ...}}}` (stdio entries use `command`/`args`/`env`). "Claude Code prompts for approval in interactive sessions before using project-scoped servers from `.mcp.json` files. To reset those approval choices, run `claude mcp reset-project-choices`."
- `claude mcp add [options] <name> -- <command> [args...]`; `-s`/`--scope` `local` (default), `project`, `user`; `-e`/`--env`; `-t`/`--transport`; `-H`/`--header`.
- `--mcp-config`: "Load MCP servers from JSON files or strings (space-separated). When you pass this flag with `-p`, Claude Code waits for still-pending servers to connect before running the first turn, up to the `MCP_TIMEOUT` startup timeout, 30 seconds by default". `--strict-mcp-config`: "Only use MCP servers from `--mcp-config`, ignoring all other MCP configurations."
- `--print`, `-p`; `--output-format` "(options: `text`, `json`, `stream-json`)"; `--input-format` "(options: `text`, `stream-json`)"; `--json-schema` "(print mode only)", result in `structured_output`; `--max-turns` "(print mode only). Exits with an error when the limit is reached. No limit by default"; `--max-budget-usd` "(print mode only)"; `--bare`: "skip auto-discovery of hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and CLAUDE.md"; "only servers supplied on the command line connect, for example with `--mcp-config`"; "bare mode doesn't use your subscription login" (needs `ANTHROPIC_API_KEY`).
- `--allowedTools`, `--allowed-tools`: "Tools that execute without prompting for permission". MCP rule syntax (permissions page): "`mcp__puppeteer` matches any tool provided by the `puppeteer` server" / "`mcp__puppeteer__*` uses wildcard syntax and also matches all tools" / "`mcp__puppeteer__puppeteer_navigate` matches the `puppeteer_navigate` tool". "Allow rules accept tool-name globs only after a literal `mcp__<server>__` prefix." "When Claude Code loads a settings file, it skips any `mcp__` rule that has parentheses." `--disallowedTools "mcp__*"` removes every MCP tool.
- `--permission-prompts`: "Pass `none` when nobody can answer, and Claude Code denies them instead... Requires Claude Code v2.1.259 or later." `--dangerously-skip-permissions`: "Equivalent to `--permission-mode bypassPermissions`." `--permission-mode` accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`.
- Output limits: "Claude Code displays a warning when MCP tool output exceeds 10,000 tokens and limits output to 25,000 tokens by default. To change the token limit, set the `MAX_MCP_OUTPUT_TOKENS` environment variable". `_meta["anthropic/maxResultSizeChars"]` raises a tool's persist-to-disk threshold "of 50,000 characters ... up to a hard ceiling of 500,000 characters" and "applies independently of `MAX_MCP_OUTPUT_TOKENS` for text content".
- Tool search: "Tool search is enabled by default: MCP tools are deferred and discovered on demand." `ENABLE_TOOL_SEARCH` values: unset, `true`, `auto` (10% threshold), `auto:N`, `false`. Per-tool `_meta["anthropic/alwaysLoad"]: true` loads upfront; server-level `"alwaysLoad": true/false` in config. Truncation: "Server instructions, and the description of a tool that loads upfront: 4,096 characters" / "The description of a tool that Claude loads through tool search: 16,384 characters" (before v2.1.296 the short limit was 2,048); `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` overrides.
- `_meta["anthropic/requiresUserInteraction"]: true` forces a prompt on every call (denied under `dontAsk` and `--permission-prompt-tool`).
- Resources: "Use the format `@server:protocol://resource/path` to reference a resource", e.g. `@github:issue://123`.
- Windows: no `cmd /c` npx note remains on the MCP page; it now only says "On Windows: Claude Code closes the server's stdin, then ends the server's process tree if the process is still running 300 milliseconds later." Tool names over 128 characters are dropped.

## 5. MCP SDKs and the 2026-07-28 spec

**CONFIRMED**
- Python SDK: latest v2.3.0, published 2026-10-02 (GitHub API). v2.0.0 published 2026-07-28: "`FastMCP` is now `MCPServer`, and there is a first-class `Client`" / "stdio servers keep handler subprocesses and stray prints off the wire, and stdout is diverted to stderr while serving." / "It supports the 2026-07-28 revision of the Model Context Protocol and serves every earlier revision from the same server." / "The tasks extension (SEP-2663) is not part of this release." / "v1.x is in maintenance mode and will only receive security fixes". v2.1.0 (24 Aug): "Raise `ToolError` / `ResourceError` when the message is meant for the model; those still reach the client and are logged at INFO without a traceback"; unexpected exceptions: "the client now sees only `Error executing tool <name>`". `requires-python = ">=3.11"` (pyproject on main). v2.3.0: "An explicit `"structuredContent": null` is checked against the output schema".
- TypeScript SDK: latest 2.3.1 published 2026-10-05; README: "This monorepo publishes split packages" (`@modelcontextprotocol/server`, `/client`, `/core`, `/node`, …), "v2 ... the stable release line, implementing the 2026-07-28 MCP spec", "Tool and prompt schemas use Standard Schema — bring Zod v4, Valibot, ArkType". `packages/server/package.json`: `"type": "module"`, `engines.node ">=20"`. Blog (https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/, June 29 2026): "It is ESM-only and runs on Node.js 20+, Bun, and Deno."
- Spec changelog https://modelcontextprotocol.io/specification/2026-07-28/changelog: removes `initialize` handshake and sessions ("Every request now carries its protocol version and client capabilities in `_meta`"); adds mandatory `server/discover`; "Multi Round-Trip Requests (MRTR) pattern introduced which replaces the previous approach of sending server-initiated requests, such as `roots/list`, `sampling/createMessage`, or `elicitation/create`. Servers return an `InputRequiredResult` (`resultType: "input_required"`)"; "All results now carry a required `resultType` field"; tasks moved to extension `io.modelcontextprotocol/tasks`; "Deprecate the Roots, Sampling, and Logging features ... log to `stderr` (stdio) or use OpenTelemetry"; `inputSchema`/`outputSchema` loosened to any JSON Schema 2020-12, `structuredContent` any JSON; `ttlMs`/`cacheScope` required on list results; `ping` and `logging/setLevel` removed. Claude Code declares `elicitation: {form: {}, url: {}}` on 2026-07-28 connections.

## 6. Licensing of a third-party QML plugin

**CONFIRMED**
- MuseScore Studio is GPL-3.0: repo `LICENSE.txt` "under the terms of the GNU General Public License version 3". The sample `share/plugins/dev_test_websocket/dev_test_websocket.qml_disabled` (main branch) is headed "SPDX-License-Identifier: GPL-3.0-only / MuseScore-Studio-CLA-applies" and uses `api.websocketserver.listen(8084, ...)`, `.onMessage`, `.send` – do not copy it.
- MuseScore's own guidance, https://musescore.org/en/handbook/developers-handbook/plugins-3x (Licensing section): "You own what you create." / "Opening in Musescore is unlikely to be the ground on which plugin script subjects to MuseScore 3 GPL licensing." / "Writing in QML language is unlikely to be the ground on which plugin script subjects to Qt licensing."
- https://musescore.org/en/about/musescore-license-policy governs code *in MuseScore's repositories*: "This code includes MuseScore plugins ... and is licensed under GNU GPL or a GPL compatible license." It does not bind external plugins. The plugin directory (musescore.org/en/plugins) has no licence field; the handbook only says plugins are "unvetted".
- Practice: tskovlund/mcp-score and ghchen99/mcp-musescore are both MIT (GitHub API `spdx_id: MIT`), each shipping a WebSocket QML plugin. jeetee's plugin repos are mostly BSD-3-Clause, some GPL-2.0, one GPL-3.0, one MIT.
- **UNCERTAIN:** forum thread https://musescore.org/en/node/352950 (July 2023) is behind a bot wall; search summary says a reply (not legal advice) held that using the plugin API or publishing on musescore.org does not by itself trigger GPL, and the question for score-editing-only plugins was left unsettled. No MuseScore developer statement on MS4 plugin licensing was found.

**Recommendation (conservative):** Write the plugin from scratch against the public API (do not copy the GPL sample), and license it under a GPL-3.0-compatible permissive licence (MIT or BSD-3-Clause), which matches MuseScore's stated "You own what you create", matches peer projects, and remains distributable alongside/inside GPL code if a court ever deemed it derivative. Keep the Python MCP server in a separate repo/package under MIT; it only speaks WebSocket to the plugin and has no GPL exposure.
