## PART A — Wire protocols of existing bridges

### A1. tskovlund/mcp-score (Python + QML, MIT, 27★, pushed 2026-10-12; targets MuseScore Studio 4.4.2+, CI on 4.4.4/4.6.2/4.7.5) — C

Sources: `src/mcp_score/musescore/plugin/mcp-score-bridge.qml`, `docs/musescore-plugin.md`, `bridge/websocket.py`, `bridge/musescore.py`, `docs/reference.md`, PRs #90/#98/#114/#120, issues #78/#108 (https://github.com/tskovlund/mcp-score).

- **Message format (C):** request `{"command": "...", "params": {...}}`; success `{"result": {...}}`; error `{"error": "Description of what went wrong"}` (docs/musescore-plugin.md). **No request ids**; correlation is one `send` followed by one `recv` with `asyncio.wait_for(..., timeout=30.0)` (`bridge/websocket.py`). Sequence failures add `failedAction`, `failedIndex`, `results`. Since PR #114, failures surface as MCP `isError: true` rather than `{"error"}` inside a successful result.
- **Batching (C):** plugin has `processSequence` ("Execute several commands in one undo step; if any step fails, all steps are rolled back… not getScore, getCursorInfo, undo or a nested processSequence"), **but no MCP tool uses it**. Each tool does 2–3 round trips (`goToMeasure`, optional `goToStaff`, then the edit); `read_passage` loops measure-by-measure.
- **Undo (C):** `withUndoStep`: `startCmd(name); try { fn() } catch { endCmd(true); throw }; endCmd(response.error !== undefined)` — per command, rollback on error; sequence runs `apply*` functions inside one step. Undo action chosen by version: `"action://notation/undo"` if 4.7+, else `"undo"`. PR #98 (merged 2026-09-25): "undo was a no-op on 4.7 (action renamed to `action://notation/undo`; chosen by version, plain `undo` on 4.4–4.6)."
- **Liveness (C):** `ping`→`"pong"`; no heartbeat; 30 s recv timeout; "A connection that breaks during the exchange is reopened once and the payload is sent again" (so a lost reply can re-apply a mutation — my reading of the code, undocumented). Port hard-coded 8765 via `api.websocketserver.listen`; **listen result is not checked**, troubleshooting only says "Verify no other application is using port 8765". QML header: "A dialog keeps the plugin instance (and its server) alive for as long as the window is open. MuseScore 4 does not support dock plugins." Docs: "Keep the window open -- closing it stops the plugin and the server with it."
- **Reading (C, minimal):** `getScore` = title, parts, measureCount, key/time sig. `getCursorInfo` = one element at measure start on one staff: CHORD→`notes[{pitch,tpc,name}]` + duration; voice "always 0 for now". No ties, tuplets, grace, dynamics, lyrics, chord-symbol reads, no whole-score dump.
- **Cursor (C):** rebuilt each command: `newCursor(); staffIdx=…; voice=0; rewind(SCORE_START); nextMeasure()×(m-1)`. No `rewindToTick`, no selection modes, no `inputStateMode`. Plugin tracks only `cursorMeasure`, so beat-level positioning is absent.
- **Compact format:** none (one MIDI pitch per `addNote`); offline path is music21→MusicXML.
- **Pitfalls (C, docs/musescore-plugin.md unless noted):** "`cursor.add` crashes MuseScore for `BAR_LINE` elements" (set `barlineType`/`repeatStart` instead); "A `HARMONY` element must be added with `cursor.add` before its `text` is set; setting `text` first crashes MuseScore"; "`Score.transpose` does not exist in MuseScore 4" (plugin shifts `pitch`/`tpc1`/`tpc2`, so key sigs/chord symbols aren't transposed); "MuseScore 4.4 moved to Qt 6 and stopped shipping the `QtWebSockets` QML module"; issue #78: on 4.7.4 `import QtWebSockets 1.0` fails and "clicking the plugin opens an empty mcp-score-bridge window that looks like success" (fixed PR #90 via `api.websocketserver`); "MuseScore hides plugins that fail to compile" (check log for `ExtensionBuilder::load | Failed to load QML file`); stale pre-0.2 QML file makes "MuseScore list two bridges" (PR #120); "Plugins cannot be started from the command line" (CI binds a shortcut in `shortcuts.xml`); issue #108: 4.7.5 on macOS 26 randomly crashes (crashpad) at startup/after export. Wrong-staff: `goToStaff` range-checks `nstaves`. Ties: not found.
- **Tools (C, 23):** connect_to_musescore, disconnect_from_musescore, connect_to_dorico, disconnect_from_dorico, get_live_score_info, ping_score_app, read_passage, get_measure_content, get_selection_properties, add_live_note, add_live_rehearsal_mark, add_live_chord_symbol, add_live_dynamic, set_live_barline, set_live_key_signature, set_live_time_signature, set_live_tempo, append_live_measures, transpose_passage, undo_last_action, generate_score, score_generation_guide, render_score.

### A2. ghchen99/mcp-musescore (Python FastMCP + QML, 117★, pushed 2026-10-13; verified on 4.7.4, PRs tested 4.6.5–4.7.5) — C

Sources: `musescore-mcp-websocket.qml`, `src/client/websocket_client.py`, `references/architecture.md`, PRs #1–#10 (https://github.com/ghchen99/mcp-musescore). Derived from JordanSucher's repo (same envelope, same `menuPath`).

- **Message format (C):** `{"action", "params"}` → `{status:"success", result}` / `{status:"error", message}`. No ids; sequential send/recv; **no timeouts**. Handler errors return `{error:"..."}` inside `result` with status still `"success"`; architecture.md: "The current Python wrappers sometimes test the inner `success` key without first unwrapping `status/result`."
- **Batching (C):** `processSequence` over a 23-action whitelist; "Processing stops at the first invalid action"; per-step results not returned.
- **Undo (C):** `executeWithUndo`: `startCmd(); try{…endCmd()}catch{endCmd(true); return {error}}` per handler. `processSequence` opens no outer cmd → each step its own undo entry. Read-only `getScoreSummary` also runs inside `executeWithUndo`.
- **Liveness (C):** `ping`; port 8765 hard-coded. PR #2 (merged): after a MuseScore restart "the client is left holding a dead websocket… until the entire MCP server process is restarted"; fix retries once, trade-off stated: "if `send` succeeds but the connection dies before `recv`, the retry could re-apply a mutating command (e.g. add a note twice)." PR #7: "an instance already holding port 8765 keeps serving." Plugin-window close: not documented.
- **Reading (C):** whole score via segment walk `elementAt(staff*4+voice)` for voices 0–3; per Chord/Rest: `name, durationTicks, isTie, isTuplet, lyrics[{text,no,syllabic}], notes[{pitchMidi,tpc,pitchName}], startTick, voice`. No grace, dynamics, chord symbols, articulations, tuplet ratio. PR #1 rationale: "whitelisting only essential musical properties (pitch, TPC, duration, voice)… fixes the >1MB overhead issue on large scores." `get_score` converts to **LilyPond text** for the LLM.
- **Cursor (C):** `inputStateMode = INPUT_STATE_SYNC_WITH_SCORE`, then `staffIdx`, `voice`, then `rewind(mode)` | `rewindToTick(startTick)` | `nextMeasure()` loop. `addNote` first syncs to the live GUI selection, then advances via `selection.selectRange`.
- **Compact format:** reads only (LilyPond). PR #10 (closed/withdrawn) proposed `read_passage`/`write_passage` with a grammar: `chord := pitch ("+" pitch)* "/" duration`, durations `w h q e s t x`, `~` tie, `[...]n:d` tuplets, `|` bars; e.g. `m35 s0: Db5+F5+Ab5/q …`; claimed "9.4 KB instead of 134 KB" and "529 characters as one call against 3,078 as 50 write_passage calls"; write "reads it back and reports whether the read-back matched".
- **Pitfalls (C):**
  - **Wrong-staff writes (PR #7):** "`SYNC_WITH_SCORE` ties the cursor's input state — including which staff it is on — to MuseScore's live GUI input state, so it overrides the explicit `staffIdx` that follows"; "a single two-note chord has been observed with the first note on one instrument and the second on another." Fix: `INPUT_STATE_INDEPENDENT`.
  - **selectRange inside startCmd silently fails (PR #8):** API doc "if selection cannot be changed, e.g. due to the ongoing operation on a score" — "startCmd() **is** such an operation"; `deleteSelection`→`cmd("delete")` "changes nothing at all… A caller reading `success` concludes the score was edited." Still unfixed on main.
  - **Ties crash (PR #9):** "`newElement(Element.TIE)` plus `cursor.add()` — crashes MuseScore… A tie with no start or end note makes the layout dereference null" (reproduced on 4.6.5). Workaround `cmd("tie")`: "It TOGGLES… It acts on a RANGE."
  - **Restart needed (PRs #7/#8/#9):** "Requires a full MuseScore restart — re-running the plugin does not reload changed code, and an instance already holding port 8765 keeps serving."
  - **Logging (PR #10):** "`console.log` is discarded by MuseScore"; use `api.log.info`. Also: "MuseScore 4.7 exposes `api.websocketserver` in the GUI but not in the console/`--extension` context."
  - `cursor.addNote(pitch, true)` stacked notes into chords (PR #5, fixed); `selectionState.elements` is an object not array (PR #3); 1-based vs 0-based measure index mismatch between `go_to_measure` and `deleteSelection`; README: "Only first verse supported"; `set_instrument_sound` only opens the dialog.
- **Tools (C, 27):** connect_to_musescore, ping_musescore, get_score, show_score, get_cursor_info, go_to_measure, go_to_final_measure, go_to_beginning_of_score, next_element, prev_element, next_staff, prev_staff, select_current_measure, select_custom_range, add_note, add_rest, add_tuplet, add_lyrics, insert_measure, append_measure, delete_selection, undo, add_instrument, set_staff_mute, set_instrument_sound, set_time_signature, processSequence.

### A3. JordanSucher/musescore-mcp (QML + Python, 30★, last push 2025-04-20) — C

Sources: plugin QML, `server.py`, README, issues #1/#3, PR #2 (https://github.com/JordanSucher/musescore-mcp).

- Same envelope as A2 (no ids, sequential, no timeouts, no retry: dead socket kept after an exception). Port 8765 hard-coded.
- **Batching:** `processSequence` (18 actions) returns `currentScore: getScoreSummary()` after the whole sequence; most single-command tools commented out.
- **Undo:** inline `startCmd/endCmd/endCmd(true)` per function; `getScoreSummary` opens its own `startCmd` and is called from inside other commands' cmd blocks (unguarded nesting); `nextStaff`/`prevStaff` early-return without `endCmd()` (code observation).
- **Reading:** whole score, **voice 0 only** (README: "Can not understand multiple voices within a staff"); fields: `name, subtype, tempo, timesig, baseDuration, dotted, durationTicks, harmonyType, accidental, tieBack, tieForward, noteType, pitchMidi, pitchName` (12-TET, no tpc), `tuplet{num,den}`.
- **Cursor:** same as A2 plus `rewindMode: 0/1/2` and `position` offset; `addNote` uses `addNote(pitch,true)` unless on a rest → unintended chords (the bug ghchen99 PR #5 fixed).
- **Pitfalls:** shipped `requirements.txt` names `websocket` while code imports `websockets` (open PR #2); issues #1 ("can't connect") and #3 (MuseScore 4 "currentScore error") unanswered.
- **Tools (C, 5):** connect_to_musescore, ping_musescore, get_score, get_cursor_info, processSequence.

### A4. romanstark/dorico-maestro (Python, AGPL-3.0, 2★, pushed 2026-10-13; tested Dorico 6.2.30 Elements) — C

Sources: `docs/protocol.md`, `src/dorico_maestro/client.py`, `server.py`, README (https://github.com/romanstark/dorico-maestro).

- **Format:** handshake `connect`→`sessiontoken`→`acceptsessiontoken`→`{"message":"response","code":"kConnected"}`; commands `{"message":"command","command":"NoteInput.Pitch?Pitch=C&OctaveValue=4","requestId":"…"}`; responses `{"message":"response","code":"kOK"|"kError","detail":"kUnknownCommand"}`. Key lesson: "Dorico responses do not include the incoming `requestId`. Responses must be correlated strictly in FIFO order" (client keeps a deque of futures). Dorico also pushes `status`/`selectionchanged`/`documentchanged` deltas.
- **Batching:** one command per round trip; `send_many` "stopping at the first failure."
- **Undo:** none; only `canUndo` status flag ("Entering note input alone pushes an undo record, so this flag confirms undo availability rather than verified placement").
- **Liveness:** scans ports 4560–4565 on `127.0.0.1` ("do not use `localhost`, as Windows resolves `localhost` to IPv6 `::1`"); connect 6 s, command 20 s, approval 60 s; no ping, no reconnect loop.
- **Reading:** "The Remote Control API is selection-based… The API does not expose the selection's pitch or bar/beat position." Whole-score read = trigger MusicXML export (modal, user must confirm) and parse with music21.
- **Write placement:** caret dead-reckoning via `NoteInput.Exit, Edit.SelectAll, NoteInput.Enter, NoteInput.MoveUpTop`, then `MoveRightBar`×n, `MoveDown`×staff, `MoveRight`×grid.
- **Pitfalls:** one-time manual "Authorize" of the session token; "kOK confirms that Dorico's UI queue accepted the command. It does not guarantee that the intended musical modification took place"; "While a modal dialog is open in Dorico, commands… return `kOK` immediately but remain unexecuted"; overwrite mode can't be verified ("cannot read bar contents back"); `NoteInput.Enter` toggles; pitch is diatonic to key → explicit accidental per note; articulations are sticky toggles; pickup bars invisible; tier-specific commands return `kUnknownCommand` on Elements; catalog "190 verified, 23 reachable, 4 unavailable, 0 broken, 131 untested."
- **Tools (C, 30):** connect_to_dorico, get_status, read_selection, add_notes, add_rest, transpose, set_time_signature, set_key_signature, navigate, switch_mode, playback, save, export_pdf, goto_bar, open_popover, run_command, score_schema, write_score, render_to_dorico, export_musicxml, read_project_info, read_score, read_open_score, import_musicxml, analyze_harmony, check_voice_leading, suggest_next_chord, instrument_range, check_counterpoint, search_commands.

### A5. ahujasid/ableton-mcp (Python + Live Remote Script over TCP, 3,185★, pushed 2026-09-22) — C

Sources: `MCP_Server/server.py`, `AbletonMCP_Remote_Script/__init__.py`, README, issues #130/#136/#138/#140, PRs #84/#97/#103/#110/#55 (https://github.com/ahujasid/ableton-mcp).

- **Format:** `{"type","params"}` → `{"status":"success","result"}` / `{"status":"error","message"}`; no ids; single socket under an `RLock`; **no length-prefix framing** — both sides accumulate chunks and retry `json.loads` until it parses (8192-byte chunks; 16 MiB cap). Version handshake `get_script_info` vs `EXPECTED_REMOTE_SCRIPT_VERSION`.
- **Batching:** none on main; issue #130 "Massive token usage" asks for "true server-side bulk operations"; PRs #97/#110 propose batches.
- **Undo:** none (no `begin_undo_step`); PR #84 open.
- **Liveness:** port 9877, `SO_REUSEADDR`; connect 5 s ×3; per-command 10 s read / 15 s modifying / 65 s audio (but #136: a reset "to 15s so the 65 s budget is never used"); pre-call `recv(1, MSG_PEEK)` liveness probe; reconnect on next call; bind failure only logged. Writes marshalled to Live's main thread via `schedule_message`; issue #140: "A write can remain scheduled after its request times out."
- **Reading:** session/track/clip; note fields `pitch, start_time, duration, velocity, mute` (+ `probability, velocity_deviation, release_velocity, note_id…` on Live 11+).
- **Write placement:** `(track_index, clip_index)`; "Writes are additive (add_notes_to_clip only appends)."
- **Compact format:** none; PR #55 "Add ASCII grid notation for MIDI patterns" open.
- **Pitfalls:** README "restart Ableton (or re-select the AbletonMCP control surface) so Live loads it"; "Only run one instance of the MCP server"; Python 2 shim for Live 10 (PR #103: "background threads suffer from severe GIL starvation"); #138 "reports success for notes Live drops"; #134 success messages read state before Live applies it; UTF-8 straddling chunks "desynchronising the connection for good"; installer path bug (#125/#85/#100); telemetry on by default until 2026-09-22 (#113/#124).
- **Tools (C, 37):** set_dataset_consent, get_session_info, get_remote_script_info, get_track_info, get_clip_notes, get_device_parameters, set_device_parameter, get_session_snapshot, create_midi_track, create_audio_track, set_track_name, create_clip, create_audio_clip, add_notes_to_clip, clear_notes_from_clip, set_clip_name, set_arrangement_clip_name, set_tempo, load_instrument_or_effect, fire_clip, stop_clip, delete_clip, start_playback, stop_playback, get_browser_tree, get_browser_items_at_path, load_drum_kit, switch_to_arrangement_view, set_arrangement_time, get_arrangement_clips, duplicate_to_arrangement, create_locator, submit_intent, rate_last_action, prefer_candidate, reject_last_action, record_audition.

### Cross-cutting lessons (all drawn from the C items above)

1. **None of the five MuseScore/DAW bridges use request ids**; all rely on strict send/recv ordering, and two (mcp-score, ghchen99 PR #2) explicitly document that reconnect-and-resend can double-apply a mutation. Dorico proves even a server-side `requestId` can be ignored, so the client must own correlation.
2. **"success" is not verification**: ghchen99 PR #8 (selectRange refused inside `startCmd`), Dorico (`kOK` ≠ executed), Ableton #138/#134. Read back after write.
3. **Undo granularity**: per-command `startCmd/endCmd(true)` is the norm; only mcp-score implements a rolled-back sequence, and no tool calls it.
4. **Context cost**: tool counts 5 / 23 / 27 / 30 / 37; only ghchen99 (LilyPond read, proposed DSL in PR #10) attacks payload size.
5. **Port 8765 hard-coded, bind failures unchecked**, in all three MuseScore bridges.

## PART B — MuseScore Studio roadmap affecting plugins

Sources: musescore/MuseScore and musescore/muse_framework (`framework/extensions/`), GitHub wiki, musescore.org release pages, issues #21659/#24360/#34210/#35226, PRs #22015/#24470/#24606/#24833/#31347/#31354/#33833/#35023.

**Extensions system (C).** Landed on master March 2024 (PR #22015 "Extensions module. Step 9"; commit "added extensions api v1" 2024-03-21), shipped in 4.4 (2024-08-27): "Plugins must be updated for Qt 6 or they won't appear in the Home screen or Plugins menu in MuseScore Studio 4.4" (https://musescore.org/en/4.4). `manifest.json` (loader `extensionsloader.cpp`): required `uri, type, title, actions`; optional `apiversion` (default 2), `ui_context`, `modal`, per-action `path, func, show_on_appmenu, show_on_toolbar`. `extensionstypes.h`: "Api versions: 1 - plugins from 3х; 2 - extensions"; `enum Type { Form /*Have UI*/, Macros /*Without UI, they just do some script*/, Composite }`. Legacy QML plugins are loaded by `legacy/extpluginsloader.cpp` as `apiversion=1, legacyPlugin=true`, becoming `Form` if `pluginType` is `"dialog"` or `"dock"`. 4.7 (PR #31354, merged 2025-12-05) adds `require("MuseApi.Log")` / `import MuseApi.Engraving` modules; PR #31347: "For older plugins (API version 1), most enums are provided as Int… For new extensions (API version 2), enums will be provided as String."

**Deprecation of legacy QML (C/R).** Wiki Manifest page: apiversion 1 is "api of old plugins, deprecated, don't use this for new extensions." **No removal date or version found anywhere.** musescore.org "4.5 and beyond" (bradleykunda, 2024-12-23): "we started developing a new extensions framework to replace the existing plugins system… we put it aside"; Tantacrul (2025-01-19): "won't negatively affect existing features or any currently working plugins"; bradleykunda (2025-11-18): "we've unfortunately had to pause work on this project… I can table this again when we start out 2026 planning"; Jojo-Schmitz (2026-09-21, R — community contributor): "There are no plans at all for a 4.8". Legacy `qmlpluginapi.cpp` is still receiving PRs (#34864, open).

**`api.*` objects (C, `extapi.h` per tag).** 4.4.4: `log, context, interactive, theme, websocket, websocketserver`; `shortcuts, navigation, keyboard, accessibility` commented out ("Providing these APIs requires approval"); `process, filesystem` commented out: "We do not control the authors of extensions; using these APIs they can deliberately or accidentally harm the user's system." 4.5.2/4.6.5/4.7: `log, interactive, theme, engraving, converter, websocket, websocketserver` (context dropped). main (Sept 2026): `MuseApi.Http`, `MuseApi.FS`; ADR 00102 (2026-07-15, Accepted): "add support for loading dynamic libraries and calling native code from JS". WebSocket: PR #24470 "[4.4.2] Added websocket api" (igorkorsukov, merged 2024-09-09, resolves #24360); test plugin `dev_test_websocket.qml_disabled` uses `api.websocketserver.listen(8084, cb)`, `.onMessage`, `.send`. Build flag `MUSESCORE_BUILD_WEBSOCKET="ON"` in CI for 4.4.4→main. ghchen99 PR #10 (C): `api.websocketserver` is undefined in the `--extension` console context.

**Persistent/dockable panels (C).** Form extensions open in `ExtensionViewerDialog.qml` (`StyledDialogView`, `alwaysAboveApp: true`); legacy `dock` is mapped to a dialog. Macros run in a session that is destroyed on return — no background lifetime; no "background" extension type exists. Issue #35226 "[PLUGINS] Restore dockable QML plugin panels in MuseScore Studio" (2026-10-13, open, 0 comments) asks for "a persistent, non-modal plugin panel… restore functionality previously available through pluginType: "dock" and dockArea". **Conclusion: a plugin cannot stay alive without a visible window** (code: dialog owns the QML instance; mcp-score docs say the same, R).

**Auto-start (NOT FOUND).** `commandlineparser.cpp` has only `--extension <uri>` for conversion jobs; no `-p/--plugin` or run-on-startup. PR #23195 (2024-06-20, "concept") proposed exec points "before and after some actions, such as creating a score, loading a score, saving" — no such register exists on main.

**Muse Hub / marketplace (NOT FOUND).** `ExtensionInstaller::installExtension` unpacks a `.mext` zip, triggered by drag-and-drop; wiki: "TODO how install third-party." Muse Hub pages list sounds/effects/apps only (R: scoringnotes).

**Release notes (C).** 4.4: Qt 6.2.4. 4.5 (2025-03-14): no plugin lines (R: 4.5.1 fixed slur/hairpin properties in the plugin API). 4.6 (2025-09-30): "Plugin API: Now includes all new elements and properties added between MuseScore 4.0 and 4.6"; Qt 6.9.x. 4.7 (2026-05-13): Qt 6.10.2; new bundled Tuning plugin. 4.7.5: 2026-09-08. R (scoringnotes): "version 4.7 will mark the final release in the MuseScore Studio 4 series"; 5.0 = automation + shared staves; news post "4.7.6 and 5.0" (~2026-10-13, 403 to fetch) — no plugin content retrievable.

**Docs site (C).** https://musescore.github.io/MuseScore_PluginAPI_Docs/plugins/html/ header "MuseScore Plugins 3.5": "This documentation corresponds to the plugins API for MuseScore 3.X version" — no 4.x section. Current 4.x docs live at https://musescore.github.io/ → `snapshots/4.5|4.6|4.7` (Engraving, Interactive, Log, Qml, Theme; no Websocket/Http pages). Issue #34210 (open): "Plugin/extension documentation is very disorganised, out of date, in many locations."

**QtWebSockets QML (C).** Issue #24360: after 4.4 "module "QtWebSockets" is not installed"; resolution was the C++ `api.websocket*`, not shipping the QML module.
